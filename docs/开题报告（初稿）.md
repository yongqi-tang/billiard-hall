## 一、选题依据及意义（不少于200字）

台球是一项室内休闲运动，近年来台球厅在城市里分布越来越广。目前大多数台球厅还是传统经营模式：顾客到店后由前台人工登记、人工计时、现金结算，高峰时段需要排队等候，离场时还要现场核对时长和费用。这种模式既耗费人力，也容易在计费和结算环节出问题，经营者很难实时掌握球台占用情况和营业收入。

移动互联网和数字支付普及之后，用手机完成预约、自助下单已经成为很多消费场景的常态。微信小程序不需要下载安装、扫码就能用，还自带支付能力，比较适合做成轻量级的自助工具。

本课题准备实现一个基于微信小程序的台球厅预约管理系统：顾客可以在小程序上查看球台状态、在线预约球台、到店后扫码自助开台、实时看到计时和费用，离场直接结账；经营者通过 Web 管理后台管理球台、订单和用户，查看营收统计。系统目标是减少前台人工环节、提高开台和结账效率，让经营者更方便地管理日常经营。

## 二、国内外研究现状及发展趋势（不少于500字）

**国外研究现状。** 国外在“预订＋自助服务”类系统上起步较早，围绕台球与体育场馆的预约管理已有较多实践。Hermawan 等[1]设计并实现了基于 Web 的台球桌预约系统，重点讨论并发控制问题，通过事务和锁避免多个顾客同时预约同一张球台时出现数据冲突，说明台球场景下的预约确实存在并发控制这一现实需求。Imanullah 等[2]将物联网技术引入台球桌管理，结合设备状态实现对球台使用情况的监控和管理，为台球厅的软硬联动提供了参考。在更广的体育场馆领域，Ghosh 等[3]面向人造草坪球场等运动场地设计并实现了在线预订系统，支持场地实时查询和在线预约，验证了场馆类预约系统的可行性。综合来看，国外研究较多集中在“预订、并发控制、设备联动”这些点上，但大多面向通用场馆或餐饮场景，专门针对国内台球厅“先付起步价、超时按分钟计费”这种经营方式的研究还比较少。

**国内研究现状。** 国内移动支付和微信小程序生态发展较快，围绕小程序开发的各类应用很多。梁浩等[4]基于微信小程序设计并实现了图书馆座位预约系统，前端用小程序、后端用 Java，提供了座位查询和预约功能，验证了“小程序＋Java 后端”这一技术组合在预约场景下的可行性。汪俊龙等[5]基于微信小程序实现了停车场车位预约系统，支持车位查询、在线预约和取消，说明小程序预约模式在公共资源管理中的适用性。张子钰等[6]研究了在线陪诊预约系统的设计与实现，讨论了预约流程和状态管理。李健斌等[7]基于微信小程序实现了高校体育互动平台，进一步印证了小程序在体育场馆场景的应用价值。年佟等[9]也基于微信小程序实现了车位预约系统，与文献[5]相互印证了该技术路线的成熟度。从这些文献可以看出，国内利用小程序开发预约类、管理类系统的技术已经比较成熟，但多数集中在图书馆、停车、餐饮等场景，针对台球厅这种“在线预约＋到店扫码开台＋按时计费”结合的场景，公开的完整设计资料仍然偏少，已有的商用产品又往往是封闭平台，不方便二次开发，也不适合作为课程设计进行系统性研究。

**发展趋势。** 从相关研究看，这类系统大致有以下几个方向：一是“小程序入口＋后端服务”的前后端分离架构，预约、计费等逻辑集中在后端，便于扩展和复用；二是把设备控制纳入系统，开台亮灯、结账灭灯，形成软硬联动；三是通过订单和营收数据辅助经营决策。本课题采用微信小程序＋Spring Boot＋MySQL 的技术方案，把在线预约和到店自助开台结合起来，并设计了可替换的设备控制层，作为对上述方向的一次实际尝试。

## 三、研究目标与主要内容（含论文（设计）提纲，不少于300字）

**研究目标。** 设计并实现一套基于微信小程序的台球厅预约管理系统，覆盖“顾客在线预约、到店自助开台、按时计费、结账离场、商家后台管理”的完整流程，系统可正常运行，计费逻辑通过测试验证。

**系统功能与用户角色。** 系统面向两类用户：

（1）顾客（普通用户）：通过微信小程序使用系统，主要功能包括：注册/登录（基于微信 openid）；查看球台列表与实时状态（空闲/使用中/维修/预约）；在线预约球台，预约成功后到店使用；扫码开台、实时查看计时与费用、续时；结账、查看历史订单、查询余额与充值记录。

（2）经营者（管理员）：通过 Web 管理后台使用系统，主要功能包括：登录；球台管理（新增、删除、设置起步价与小时价、处理预约）；订单管理、用户管理；查看球台占用、营收统计。

**主要内容：**

1. **需求分析与系统设计**：梳理顾客、经营者两类角色的功能需求，完成用例分析、总体架构设计和数据库设计（用户、球台、预约、订单、设备、充值流水等数据表）。
2. **预约功能设计**：设计在线预约流程，包括球台状态查询、预约下单、预约到期自动释放/提醒、并发预约冲突处理，并与到店开台流程衔接。预约记录按“待使用/已开台/已完成/已取消/超时释放”五种状态管理；同一球台同一时段只允许一个有效预约，重复预约由后端事务与数据库约束双重拦截；用户到店扫码开台时系统自动核销对应预约；预约开始后 30 分钟内未到店由定时任务自动释放，避免占用球台。
3. **计费模型设计**：设计“起步价含起步时长、超出按分钟计费”的计费方式，实现开台扣费、续时扣费、结账多退少补，以及欠费处理策略。
4. **后端服务实现**：基于 Java＋Spring Boot＋MyBatis-Plus＋MySQL 实现 REST API，包括预约、开台、计时、结账、充值等接口，并实现定时任务（预约超时释放、欠费检查）。
5. **微信小程序客户端**：实现首页球台列表、预约、扫码开台、计时、续时、结账、订单历史、余额与充值等页面。
6. **Web 管理后台**：实现球台管理、预约管理、订单管理、用户管理与营收统计。
7. **测试与验证**：对计费算法进行单元测试，对预约、开台、结账等核心流程进行接口测试，验证功能正确性。

**论文（设计）提纲：**

- 第1章 绪论（研究背景、国内外研究现状、研究目的和意义、研究内容）
- 第2章 系统分析（非功能需求分析、功能需求分析、可行性分析、系统关键技术、本章小结）
- 第3章 系统设计（系统概要设计、数据库设计）
- 第4章 详细设计（登录功能、后端详细设计：预约/开台/计时/结账等模块、前端详细设计）
- 第5章 系统实现（系统页面展示、各功能模块实现）
- 第6章 软件测试（测试环境、测试用例、测试结果）
- 第7章 总结与展望

## 四、拟采用的研究方法及手段

1. **文献研究法**：查阅小程序开发、Spring Boot、数据库设计和预约系统相关文献与官方文档，学习现有方案，为系统设计提供参考。
2. **软件工程方法**：按“需求分析→总体设计→详细设计→编码实现→测试验证”的流程推进，用用例图、E-R 图、架构图等表达设计。
3. **前后端分离开发**：后端提供 RESTful API，小程序和管理后台共用同一套接口，接口返回统一的结果格式。
4. **数据库建模**：使用 MySQL 建库建表，预约、开台、结账等关键操作放在事务中执行，保证余额、订单、球台状态的一致性；预约采用数据库约束处理并发冲突。
5. **自动化测试**：编写接口测试脚本对运行中的后端进行验证，用断言检查计费与预约流程的正确性。
6. **软硬件解耦设计**：设备控制通过抽象层实现，用模拟实现支撑系统在无真实硬件环境下运行，也便于后续替换。
