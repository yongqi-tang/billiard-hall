## 一、选题依据及意义（不少于200字）

随着移动互联网和数字支付的普及，传统台球厅仍普遍采用"人工登记、现金结算"的经营模式，存在三方面突出问题：一是人力成本高，需要专人负责开台登记、计时结账和收银；二是效率低，高峰时段排队等待明显，顾客体验差；三是管理粗放，营收数据依赖人工统计，账目易错、缺乏实时经营数据支撑。

微信小程序具有"无需安装、即扫即用、天然携带支付能力"的特点，是轻量级自助服务的理想载体。本课题设计并实现一个基于微信小程序的自主台球厅管理系统，顾客扫码即可自助开台、实时计时、续时与结账，球台灯光随开台/结账自动联动；经营者通过 Web 管理后台可实时查看球台状态、订单流水与营收统计。该系统能显著降低台球厅人力成本、提升运营效率，并为中小型台球厅的数字化转型提供一套低成本、可落地的参考实现，具有明确的工程应用价值。

## 二、国内外研究现状及发展趋势（不少于500字）

**国外研究现状：** 国外无人化/自助化消费场景起步较早。在体育休闲领域，欧美国家已出现基于自助终端或移动 App 的预订与计费系统，其特点是与成熟的 SaaS 收银、会员营销体系深度集成，支持在线预订、动态定价与信用账户。但由于国外社交生态、支付习惯与国内差异较大，国外方案多为独立 App 或浏览器端，缺少与微信这类国民级应用的无缝衔接，且系统成本高、本地化适配不足，难以直接在国内中小台球厅落地。

**国内研究现状：** 国内移动支付与小程序生态发展迅速。围绕"自助运动场馆"，市面上已有部分商用产品（如部分台球厅的无人值守系统），核心功能包括扫码开台、自动计时、余额结账、硬件联动等。然而商用产品存在以下普遍问题：一是多为封闭的 SaaS 平台，数据归属商家，二次开发困难；二是技术方案不透明，难以作为毕业设计进行系统性研究与复现；三是价格与硬件绑定销售，初始投入大。学术与工程领域针对"台球厅"这一细分场景的完整系统设计（含数据库设计、计费算法、设备控制联动、管理后台）的公开资料较少，多数集中在通用的"体育场馆预约系统"层面，缺少针对台球厅"先付起步价、超时按分钟计费、灯光联动"业务特性的深入建模。

**发展趋势：** 结合当前技术发展，自主台球厅管理系统呈现三个趋势：一是"轻前端 + 强后端"架构，小程序作为入口，业务逻辑、计费与数据统一沉淀在后端，便于多端复用；二是软硬联动，通过 IoT 设备（灯光、闸机、门禁）实现"开台亮灯、结账灭灯"的自动化闭环；三是数据驱动经营，通过营收统计、订单分析辅助商家决策。本课题采用前后端分离架构，以微信小程序为客户端、Spring Boot 提供 REST API、MySQL 持久化数据，并设计设备抽象层模拟灯光联动，正是对这一趋势的一次完整实践。

## 三、研究目标与主要内容（含论文（设计）提纲，不少于300字）

**研究目标：** 设计并实现一套功能完整、可运行的自主台球厅管理系统，包含微信小程序客户端、Web 管理后台和 REST 后端服务三部分，覆盖"顾客自助开台—计时计费—结账离场—商家运营管理"的全流程，并保证系统的正确性（计费与状态机通过自动化测试验证）。

**主要内容：**

1. **需求分析与系统设计**：梳理顾客端与商家端两类角色、六个核心业务（登录、充值、开台、计时、续时、结账、取消）的用例，完成数据库逻辑设计与物理设计（用户、球台、订单、设备、充值流水五张表）。
2. **计费模型设计**：设计"起步价含起步时长 + 超出按分钟计费"的阶梯计费算法，实现多退少补、续时流水与欠费强制结账策略。
3. **后端服务实现**：基于 Java 17 + Spring Boot + MyBatis-Plus + MySQL 实现 REST API 与定时任务（欠费检查）；设计支付抽象层与设备抽象层，使系统可在无真实微信支付、无真实硬件的情况下运行与演示。
4. **微信小程序客户端**：原生小程序实现首页球台列表、扫码开台、实时计时、续时/结账/取消、订单历史、余额与模拟充值等页面。
5. **Web 管理后台**：基于 Vue 3（本地化、不依赖外网 CDN）实现球台管理、订单管理、用户管理与营收统计，并内嵌进后端 jar 便于单机部署。
6. **测试与验证**：编写计费算法单元测试与真实后端集成测试，覆盖登录→充值→开台→计时→续时→结账→统计全流程。

**论文（设计）提纲：**
- 第1章 绪论（选题背景与意义、国内外现状、研究内容）
- 第2章 相关技术介绍（微信小程序、Spring Boot、MyBatis-Plus、MySQL）
- 第3章 系统需求分析与总体设计（用例分析、架构设计、数据库设计）
- 第4章 系统详细设计与实现（计费模型、核心接口、小程序页面、管理后台、软硬联动）
- 第5章 系统测试（测试方案、集成测试结果、结果分析）
- 第6章 总结与展望

## 四、拟采用的研究方法及手段

1. **文献研究法**：查阅小程序开发、前后端分离架构、计费系统设计等相关文献与官方文档，梳理技术方案。
2. **软件工程方法**：按"需求分析→总体设计→详细设计→编码实现→测试验证"的标准流程推进，采用用例图、E-R 图、架构图等表达设计。
3. **前后端分离开发**：后端提供 RESTful API，小程序与管理后台复用同一套接口，接口返回统一结果格式（code/message/data）。
4. **数据库建模与事务**：使用 MySQL 建库建表，开台/结账/取消等关键操作采用数据库事务保证余额与订单一致性。
5. **自动化测试手段**：编写 Node.js 集成测试脚本，对真实运行的后端进行端到端验证，用断言保证计费正确性与状态机完整性。
6. **软硬件解耦设计**：设计设备控制抽象层与支付抽象层，通过可替换的模拟实现（Mock）支撑系统在无真实硬件与第三方支付环境下运行演示，也便于后续替换真实实现。
